# OpenEmpiric v1.0.4

## Release Overview

OpenEmpiric v1.0.4 hardens project-context resolution, active-work state, preflight reliability, and memory retrieval quality. The release focuses on reducing noisy or contradictory OEM health/preflight signals while improving deterministic ranking for technical memory, directives, and active work.

## What Changed and Why

### 1. Field-Aware Active Work

- **Change**: Added a field-aware active-work model that separates `workspace_root`, `memory_root`, `active_work_item`, `active_topic`, and `active_task`.
- **Why**: OEM no longer treats repository roots or memory roots as the current task. Health/preflight now detects contradictions at the right semantic field instead of collapsing everything into a single active-project string.

### 2. Safe Active-Work Repair

- **Change**: Added `oem active-work repair --dry-run` and `oem active-work repair --apply` for repairing stale handoff/runtime active-work conflicts.
- **Why**: Stale handoff files can now be repaired safely without rewriting outcomes history or deleting memory concepts. Repairs create backups under `.oem/.backups/active-work-repair/<timestamp>/`, derive the canonical work item from runtime-context evidence, and return `unsupported_repair_case` when no safe runtime work item exists.

### 3. Health And Preflight Consistency

- **Change**: Unified active-work contradiction reporting across `oem health`, `knowledge_read(scope="health")`, and MCP health checks.
- **Why**: Debugging no longer has to reconcile different contradiction counts or mismatched active-project displays across OEM surfaces.

### 4. Memory Ranking Improvements

- **Change**: Added boundary-aware technical identifier matching, type-aware boosts, relevance floor filtering, and a memory-ranking harness with golden queries.
- **Why**: Technical handoffs, workarounds, decisions, and exact identifiers rank more predictably while weak incidental matches are filtered out.

### 5. Directive And Instruction Matching Hardening

- **Change**: Improved directive matching with stopword/generic-token guardrails, deduplication, and instruction ledger support.
- **Why**: Generic phrases like health checks and current-work wording are less likely to trigger unrelated required directives.

### 6. Runtime Provenance And Debugging

- **Change**: Added runtime provenance detection for editable installs, no-config debug CLI wrappers, and expanded health warnings for dev checkout runtime serving non-dev projects.
- **Why**: OEM can now explain where its runtime is loaded from and makes development-vs-installed-runtime mismatches visible.

## Install

To install/update this version using `uv`:

```bash
uv tool install "git+https://github.com/xpajonx/openempiric.git#subdirectory=packages/oem-knowledge[semantic]"
```
